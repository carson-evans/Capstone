# Contributing

Thanks for contributing to CommonMASS.

## Branch flow
- Create feature branches from `dev`
- Open pull requests into `dev`
- `main` is for milestone/release-ready code only

## Before opening a pull request
- Pull the latest changes from `dev`
- Test your changes locally
- Make sure the app builds if your change affects frontend code
- Do not commit secrets, API keys, `.env` values, or credentials

## Commit guidance
- Use clear commit messages
- Keep pull requests focused on one change when possible

## Pull request expectations
Please include:
- what changed
- why it changed
- anything that needs special review
- screenshots for UI changes when relevant

## Code style
- Keep changes readable and minimal
- Reuse existing project structure where possible
- Avoid deleting core functionality without team agreement

## Security
If you find a security issue, do not open a public issue. Follow the instructions in `SECURITY.md`.
